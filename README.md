# Research Review Agent — V1 Experimental

A topic-neutral research-review workflow with explicit human decisions and traceable evidence, from a research question to source-grounded writing.

**Experimental, not a fully autonomous researcher or a completed systematic-review service.** The Python CLI manages state, provenance, schemas and gates. Codex or a researcher develops the protocol, interprets papers and writes arguments using the bundled procedures. A parser does not perform scientific reasoning, and validation is not scientific approval.

## What is included

- All **19 phases (0–18)** in one authoritative [workflow registry](workflow/phases.json), with [ordinary Markdown procedures](workflow/procedures/README.md).
- Research-question initialization, draft Protocols, controlled pre-approval amendments, state journals and recovery.
- Crossref/OpenAlex metadata adapters, citation expansion, conservative identity resolution and recorded coverage limits.
- Authorized PDF acquisition/local import, DocumentVersions, SHA-256, page parsing and SourceAnchors.
- Versioned title/abstract/full-text screening proposals, human review records and coverage checks.
- Structured Reading Notes, multiple Evidence Items per paper, composable domain extensions and source tracing.
- Evidence-grounded theme/method/boundary organization, Claims and normalized evidence links.
- Outlines, Section Briefs, versioned draft spans, citation export, audit records and final human QC checks.

The **No-Skills / workflow-first** architecture uses [AGENTS.md](AGENTS.md), the registry, procedures and CLI. No personal/global Codex Skills, model SDK or model API key is required by the Python package. Scientific judgment is not generated by Python alone.

## Install

Python **3.11+** is required. The core runtime uses the standard library; building requires the declared `setuptools>=68` backend.

```bash
git clone https://github.com/slimseal/research-review-agent.git
cd research-review-agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
rragent --help
```

On Windows PowerShell, activate with `.venv\Scripts\Activate.ps1`.

For PDF parsing, install the existing optional dependency:

```bash
python -m pip install -e '.[pdf]'
```

This pins `pypdf==6.20.1`; installation can require network access. A separate local PDF viewer/renderer is needed for visual checking of tables and glyphs. Missing parser support is reported, not replaced with model memory. See [installation](docs/installation.md) and [external dependencies](docs/external-dependencies.md).

## Quick Start: create a draft, not an approval

```bash
rragent init \
  --question "How do novice teachers describe developing classroom authority?" \
  --domain "education" \
  --output reviews/my-review

rragent validate --project reviews/my-review
rragent next --project reviews/my-review
rragent phase-context --project reviews/my-review --phase 0
```

Initialization creates a structured blank draft. It does **not** produce a completed protocol or execute a literature search. Open this repository as the Codex workspace and ask:

> Follow AGENTS.md and the registered workflow for reviews/my-review. Develop a substantive Phase 0 Protocol from my research question, using an appropriate research design rather than a fixed PICO template. Record unresolved choices. Do not approve the Protocol, search, download or advance a phase. Stop for my review.

Then inspect the populated draft:

```bash
rragent protocol-status --project reviews/my-review
rragent validate --project reviews/my-review --require-substantive-protocol
```

Human approval is a separate deliberate operation documented in the [tutorial](docs/tutorial.md), not part of this quick start. Continue through `next` → `phase-context` → the registered procedure → validation. Do not advance around reported blockers.

## The workflow

| Phases | Work |
|---|---|
| 0 | Review Protocol and human approval |
| 1–2 | Search concept map and provider-specific search strategy |
| 3–5 | Scholarly discovery, citation expansion, lawful acquisition and registry |
| 6–8 | Screening, full-text reading and evidence extraction |
| 9–12 | Initial synthesis, boundaries, Claims and corpus-bounded gap analysis |
| 13–16 | Argument structure, Section Briefs, drafting and bibliography |
| 17–18 | Independent claim-evidence audit and human quality control |

Protocol approval, Gate 1 (screening before reading), Gate 2 (evidence before drafting), Gate 3 (Claims before gaps) and final human QC remain enforced. When an independent-evaluation policy is registered, formal Phase 9 and downstream entry also require the current evaluation gate. Declared reviewer names and attestation flags are **not identity authentication**.

## Real demonstration versus engineering fixtures

See the [public V1 demonstration](examples/v1-demo/README.md), including a [single-study English sample](examples/v1-demo/SINGLE_STUDY_SAMPLE.md).

Two distinct runs supplied the demonstrated results:

- **Formal pilot:** six metadata queries returned 150 occurrences / 147 provisional Paper IDs; six citation requests added 32 IDs. All 179 candidates received machine screening suggestions: 2 continue, 129 exclude, 48 uncertain. These are not final human inclusion/exclusion decisions. Formal Gate 1 remained blocked.
- **Isolated functional test:** one lawfully imported real paper produced Reading Notes, 8 Evidence Items, 4 Claims, 14 links, an outline, a Section Brief and four source-traceable English paragraphs. These provisional engineering outputs are not a formally approved multi-study review.

Only curated summaries, paraphrased results and the bounded sample are included publicly. No research approval logs, private identity records, full-text PDF, raw provider responses or personal paths are distributed. Synthetic tests and teaching examples are explicitly separate from real-source demonstrations.

## Provider access and data boundaries

```bash
rragent capabilities
rragent provider-status
```

These inspect implementation/configuration, not successful network connectivity. Provider requirements and quotas can change; check the provider before an authorized live operation. Supported environment variables include `OPENALEX_API_KEY`, `CROSSREF_MAILTO`, `CROSSREF_PLUS_API_TOKEN` and `OPENCITATIONS_ACCESS_TOKEN`. Use your own authorized credentials and budget. Never commit secrets; `.env` files are not automatically loaded.

Search and acquisition are explicit operations requiring appropriate workflow state and authorization. No paywall, login, CAPTCHA or rate-limit bypass is supported. Metadata is not full-text evidence; missing abstracts do not by themselves justify exclusion. Raw data and approvals belong in private research workspaces, preferably outside this repository.

## Known limitations

- The single-paper demonstration is not a cross-paper synthesis, systematic-review coverage claim, causal finding or validated research gap.
- Whole-library bibliography validation can be blocked by duplicate titles among uncited candidates. The demonstrated writing validation did **not** pass.
- PDF extraction can emit NUL/control characters for minus glyphs; exact numerical values require visual verification or an explicit uncertain state. Robust automatic table recognition/OCR is not provided.
- Legacy screening CSV compatibility and large-journal performance have known limitations.
- Native lab exports may have generic review titles; always label provisional outputs explicitly.
- Independent scientific evaluation and final human audit were not completed for the real single-paper demonstration. Lab work cannot complete formal research phases.
- No guarantee is made that all source claims are correct or that every external service is available. No new full-suite or live integration run was performed solely for publication preparation.

See [known issues and validation scope](docs/KNOWN_ISSUES.md).
